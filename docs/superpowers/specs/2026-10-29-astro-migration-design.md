# Astro への移行とヘッダー・フッターの共通化

## 背景と目的

このサイトは素の HTML 9 ページを GitHub Pages（main ブランチの `/` をそのまま配信）で公開している。ヘッダー・フッターは各ページに直接書かれていて、次のようにばらついている。

- 言語切り替えの方式が混在している。トップと各アプリのページは 1 ページ内のボタンで切り替え（`assets/lang.js`）、no-smoking-bank と picture-this のプライバシーポリシーは `/ja/` と `/en/` の別ページ、identify-app は日本語のみ。
- ヘッダーの中身がページによって違う（ロゴと言語ボタン、アプリのアイコンと名前など）。
- プライバシーポリシーからトップへ直接戻るリンクがない。

Astro を導入し、ヘッダー・フッター・`<head>` を共通のコンポーネントにして、全ページで同じ見た目・同じ導線にする。

## ゴール

- 全ページのヘッダー・フッターが 1 か所の定義から生成される。
- 言語切り替えは「日英で別ページに分け、相手の言語の同じページへリンクする」方式に全ページでそろえる。
- どのページからもトップへ戻れる。
- 既存の公開 URL はすべてそのまま使える。

## やらないこと

- React などの UI フレームワークの導入。ブラウザで動かす処理は素の JavaScript で書く。
- identify-app の英語版の作成。
- ページ本文の内容やデザインの作り直し。本文は既存の HTML をそのまま移す。

## 失敗とみなすこと

- 既存の URL（特にストアに登録しているプライバシーポリシーの URL）が 404 になる。
- `app-ads.txt` がサイト直下で配信されなくなる。
- Google アナリティクスのタグが一部のページから消える。
- 英語環境の人が日本語版を選んだのに、英語版へ押し戻される。

## 技術の選択

- Astro を使う。React などは入れない（ユーザーと合意済み）。
- GitHub Actions で Astro をビルドし、GitHub Pages に公開する。公開元の設定を「main ブランチから配信」から「GitHub Actions」に切り替える必要がある。この切り替えはリポジトリ設定の変更なので、実施前にユーザーに確認する。

### 公開の切り替え手順

サイトが表示されない時間を作らないため、次の順で進める。（実装側の判断）

1. Astro のソースとデプロイ用のワークフローを PR にまとめる。PR の時点でビルドが通り、出力に既存の全 URL と `app-ads.txt` が含まれることを確認する。
2. マージの直前に、ユーザーの確認を取ってから `gh api` で公開元を「GitHub Actions」に切り替える。切り替えても、新しいデプロイが終わるまでは今公開されている内容が配信され続ける。
3. PR をマージし、ワークフローのデプロイが終わったら、既存の URL がすべて表示されることを確認する。

## 言語の扱い

### URL

- 日本語版は既存の URL をそのまま使う（`/`、`/no-smoking-bank/`、`/picture-this/`、`/identify-app/`、`/identify-app/privacy-policy/`）。
- 英語版は新しく `/en/` を付けた URL を作る：`/en/`、`/no-smoking-bank/en/`、`/picture-this/en/`。
- プライバシーポリシーは既存の `/no-smoking-bank/privacy-policy/ja/`・`/en/` と `/picture-this/privacy-policy/ja/`・`/en/` をそのまま使う。
- identify-app は日本語のみ。英語版は作らない。

### 言語切り替えのリンク

- ヘッダーの右側に、相手の言語の同じページへのリンクを置く。全ページで同じ位置・同じ見た目にする。
- 英語版がないページ（identify-app とそのプライバシーポリシー）ではリンクを出さない。

### 英語環境での自動移動

- 言語が URL に入っていない日本語版のページ（`/`、`/no-smoking-bank/`、`/picture-this/`）だけが対象。ブラウザの言語が日本語以外なら英語版へ移動する。
- `/privacy-policy/ja/` のように URL で言語を指定しているページは移動させない。
- 英語版がないページ（identify-app）は移動させない。
- ヘッダーのリンクで言語を選び直したら、選んだ言語をブラウザに保存する。保存した言語があるときはブラウザの言語より優先する。保存が `ja` なら移動させず、`en` なら英語版へ移動する。（実装側の判断）
- `/en/` のページから日本語版へ自動で移動させることはしない。（実装側の判断）
- 保存には今の `lang.js` が使っている `lang` キーを使わず、新しいキーを使う。今のキーは言語を選んでいない人にも自動判定の結果が書き込まれているため、選び直した人と区別できない。（実装側の判断）

### 検索エンジン向け

- 英語版があるページには、日英それぞれの URL を示す hreflang の `<link>` を入れる。

## ヘッダー・フッターの中身

### ヘッダー

- 左：今いるアプリのアイコンと名前。そのアプリのページ（同じ言語）へのリンク。トップページではサイト名「SHINESPARK」を出す。
- 右：言語切り替えのリンク（英語版があるページのみ）。

### フッター

- アプリのページとプライバシーポリシーには、そのアプリのページへのリンクと、プライバシーポリシーへのリンクを出す。
- トップへ戻るリンク（今の「ほかのアプリ」）を全ページに出す。英語版のページからは英語版のトップへ戻す。
- 今アプリのページのフッターにある App Store へのリンクは残す。アプリごとの URL を共通フッターに渡して出す。（実装側の判断）
- お問い合わせ（Google フォーム）へのリンクはアプリごとに出し分ける。フォームはアプリ専用で、ほかのアプリと共用しない。
  - identify-app：identify-app 専用のフォーム（`https://docs.google.com/forms/d/e/1FAIpQLScOjpxN7rwKPgArAJ1ulaLDwoQ6MJKAzvvT1nytPRdNrWqAMw/viewform`）
  - no-smoking-bank：no-smoking-bank 専用のフォーム（`https://docs.google.com/forms/d/1O_JKH8uG6Xcj0YK0Dyldgm1jr2FIXeTnW4S4r6BVZBk/viewform`）
  - picture-this：問い合わせリンクを出さない。今 picture-this のページのフッターにある no-smoking-bank のフォームへのリンクは削除する。picture-this のプライバシーポリシー（日英とも）の「問い合わせ」の節は、見出しごと削除する。
- X のアカウントへのリンク（`X: @shnsprk`）とコピーライトを全ページに出す。

## 共通の `<head>`

- Google アナリティクスのタグ（測定 ID `G-C90LV9QWZD`）を全ページに入れる。
- title、description、OGP、favicon はページごとに値を渡して生成する。英語版のページには英語の値を用意する。

## そのまま残すもの

- `app-ads.txt` はサイト直下で配信し続ける。
- 画像（各アプリの `img/`、`favicon.png`、`herdr-streamdeck/icon.png`）は今と同じ URL で配信する。

## 実装者に任せること

- ディレクトリ構成、コンポーネントの分け方と名前。
- ページごとの CSS をどこまで共通化するか。ヘッダー・フッターの見た目は全ページでそろえること。
- 英語版のページ本文は、今の `<span class="en">` の文言から作る。
- 選んだ言語の保存方法（localStorage など）。
